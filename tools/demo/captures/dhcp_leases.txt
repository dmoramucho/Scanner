# An ISC `dhcpd.leases` extract for the demo estate.
#
# This is the second source, and DHCP rather than mDNS on purpose. mDNS announces a hostname
# and an address and nothing else — both weak anchors — so an mDNS record can never merge with
# an ARP sighting and would leave every host in this estate split across two assets. A DHCP
# lease carries the MAC *and* the hostname in one record, so entity resolution joins it to the
# ARP sighting on the strong anchor and the asset ends up with both.
#
# 10.10.60.88 is deliberately absent: it answers ARP and holds no lease, which is what a
# statically-addressed device nobody wrote down looks like. It stays unidentified, and that is
# the shadow-IT case the triage queue exists for.
#
# The last block is `free` on purpose — an expired lease is the absence of a device, and the
# parser has to drop it rather than report a host that went home.

lease 10.10.10.11 {
  starts 6 2026/08/16 09:15:00;
  ends 6 2026/08/16 21:15:00;
  binding state active;
  hardware ethernet 00:50:56:a1:00:11;
  client-hostname "web-01";
}
